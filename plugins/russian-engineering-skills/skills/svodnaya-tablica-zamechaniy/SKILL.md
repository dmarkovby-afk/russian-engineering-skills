# Сводная таблица замечаний

Выполняй задачу строго по шагам ниже.

## 1. Поиск входных данных

1. Найди в папке `Кодекс/Замечания` подпапку или набор архивов, относящийся к текущей дате.
2. Для каждого архива создай одноименную папку рядом с архивом.
3. Распакуй содержимое архива в эту одноименную папку.
4. Сформируй список всех PDF-файлов с замечаниями из распакованных папок.
5. Обрабатывай замечания строго по одной папке: выбери одну папку раздела/пакета, извлеки PDF только из нее, создай/обнови таблицу по этой папке, проверь результат, и только после этого переходи к следующей папке. Не обрабатывай все папки одним массовым проходом, если пользователь прямо не попросил общий пакетный запуск.

## 2. Определение раздела

1. Разделяй два типа выходных таблиц:
   - таблицы в папке `Сводные таблицы из PDF` — это сводные по исходным папкам экспертов; они создаются строго из PDF одной исходной папки и не дублируют замечания по нескольким томам;
   - таблицы `Замечания по Объекту ... <Раздел> <YYYY-MM-DD>.xlsx` в папке `Замечания` — это таблицы по исполнителям/разделам ПД; для них применяй разнесение по ссылкам на материалы.
2. Для разнесения замечаний по исполнителям главный источник раздела: блок `Ссылка на материалы, в отношении которых сделан вывод о несоответствии`.
3. Если в ссылке на материалы указан раздел проектной документации (`Раздел 01. Пояснительная записка`, `Раздел 03. ...`, `Подраздел 2. ...` и т.п.), относить замечание к этому разделу ПД, а не к разделу эксперта/пакета.
4. Если в ссылке на материалы указано несколько томов/разделов ПД, одно и то же замечание нужно включить в таблицу каждого указанного раздела-исполнителя. Не выбирай только первый раздел.
5. Для всех пакетов без исключения применяй правило `Раздел 01. Пояснительная записка` -> `1 ПЗ`.
6. Если ссылка на материалы пустая или не содержит раздел ПД, используй явное указание раздела ПД в тексте `Вывод о несоответствии` или `Предложения по отработке замечания`, если там сказано, какой раздел нужно исправить (например, `Раздел «Пояснительная записка»` -> `1 ПЗ`).
7. Только если раздел ПД не удалось определить по материалам и тексту замечания, используй имя PDF (`..._Раздел <X>_Пакет...`) или имя распакованной папки (`...Раздел <X>`).
8. Если в имени есть префикс `Раздел`, убирай его.
9. Список титульных листов из папки `Кодекс` используй как проверку полноты и словарь соответствий, но не как замену уже найденного раздела ПД.
10. Не подменяй человекочитаемые разделы кодами из титулов (`ИОС2`, `ИОС4` и т.п.). Для итоговой таблицы используй короткие обозначения разделов: `1 ПЗ`, `СПОЗУ`, `АР`, `КР`, `ЭС`, `ВК`, `ОВ`, `УСС`, `ГС`, `ТХ`, `ПОС`, `ЭЭ`, `ПБ`, `ИТМГОЧС`, `СМ`, `ЦИМ` и т.д.
11. Если в материалах или имени файла есть `Технологические решения`, `ТХ` или файл вида `_ТХ_...`, относить замечание к разделу `ТХ`, даже если в пути также указано `Раздел 06`. Не классифицируй такие замечания как `ПОС`.
12. Если пакет/папка называется `ТР (ТХ)` или имя PDF содержит `_Раздел ТР_`, для этого проекта нормализуй раздел как `ТХ`, чтобы отдельный файл назывался по разделу `ТХ`.

## 3. Правила извлечения из PDF

Соблюдай правила без исключений:

- НЕ сокращай текст.
- НЕ перефразируй.
- НЕ объединяй пункты.
- НЕ додумывай отсутствующее.

Разрешено только:

- убрать переносы строк;
- исправить символы (ошибки распознавания, кодировки, артефакты OCR).

Дополнительно для формы замечаний:

- извлекай текст в двух режимах: `-layout` и обычный (`без -layout`);
- для полей, где значение стоит между строками заголовка (например, `Направление деятельности ... эксперта:`), используй `-layout`;
- для длинных блоков (`Вывод о несоответствии`) используй обычный режим;
- для `Предложения по отработке замечания` извлекай обе части значения:
  - часть между строками заголовка `Предложения по отработке ... замечания:`;
  - продолжение после `замечания:` до конца формы;
  - затем объединяй их в одну строку;
- из хвоста `Предложения...` удаляй служебную фразу `Требуется внесение изменений или добавлений в документацию.`;
- блок `Обсуждение` внизу PDF извлекай отдельно и записывай в `Ответ исполнителя`, а не в `Предложения`.

## 4. Структура итоговой Excel-таблицы

Используй файл `assets/template-summary-remarks.xlsx` как обязательную основу. Не создавай оформление заново, если шаблон доступен.

Создай файл Excel со столбцами в точном порядке:

1. `№`
2. `Дата`
3. `Направление деятельности эксперта`
4. `Раздел`
5. `Вывод о несоответствии`
6. `Ссылка на требования / нормативы`
7. `Предложения по отработке замечания`
8. `Ответ исполнителя`

По умолчанию сохраняй один лист в формате шаблона. Создавай свод по разделам и дополнительные листы только по прямому запросу пользователя.

Если пользователь просит анализ или отработку замечаний, заполняй `Ответ исполнителя` конкретными действиями, местами внесения изменений и готовой формулировкой ответа.

Если в PDF внизу есть блок `Обсуждение` (переписка заявителя и эксперта), переноси его 1:1 в колонку `Ответ исполнителя`. Не клади обсуждение в `Предложения по отработке замечания`: это поле формы остаётся как в бланке, а при пустом бланке — `Не указано`. Оставляй `Ответ исполнителя` пустым только если блока `Обсуждение` нет и пользователь не просил составлять ответы.

## 5. Форматирование Excel

Сохраняй ширины столбцов, шапку, шрифты, заливку и границы из `assets/template-summary-remarks.xlsx`.

Если шаблон технически недоступен, используй базовые границы ширин столбцов:

- A: 6-8
- B: 16-24
- C: 24-56
- D: 10-24
- E: 30-95
- F: 26-90
- G: 30-95
- H: 30-95

Применяй формат:

- включи перенос текста во всех заполненных ячейках;
- выравнивай по верхнему краю;
- устанавливай высоту строк автоматически по объему текста;
- не объединяй ячейки;
- копируй формат строки-образца на каждую новую строку замечания;
- закрепляй строку заголовков.

Правило по ширине:

- подбирай ширину по фактическому тексту в колонке;
- ограничивай ширину указанными диапазонами, чтобы лист не разъезжался.

## 6. Правила заполнения

1. Переноси текст строго 1:1 из PDF с учетом разрешенных преобразований.
2. Поле нормативки записывай в одну строку.
3. Списки внутри текста сохраняй.
4. Каждое замечание записывай отдельной строкой.
5. Не объединяй разные замечания в одну строку.
6. Если любое текстовое поле пустое в PDF (`Дата`, `Направление деятельности эксперта`, `Раздел`, `Вывод о несоответствии`, `Ссылка на требования / нормативы`, `Предложения по отработке замечания`), заполняй значением `Не указано`.

## 7. Проверка перед выдачей

1. Проверь, что все архивы текущей даты распакованы в одноименные папки.
2. Проверь, что все найденные PDF обработаны.
3. Проверь, что разделы заполнены из пакетов замечаний и не подменены кодами титульных листов.
4. Проверь, что восемь колонок, ширины, темно-синяя шапка, белый текст заголовков, границы и переносы соответствуют `assets/template-summary-remarks.xlsx`.
5. Проверь количество пустых полей по колонкам: пусто только там, где пусто в исходном PDF.
6. Проверь, что в текстовых колонках нет пустых значений (пустые должны быть заменены на `Не указано`).

## 8. Результат

Выдай готовый Excel-файл со сводной таблицей замечаний. Перед выдачей обязательно отрендери заполненный лист и визуально проверь, что весь текст виден и не обрезан.

## Эталонный шаблон

Шаблон: `assets/template-summary-remarks.xlsx`.

Он создан по файлу `Ответы на замечания 26.06.xlsx` и содержит:

- восемь колонок от `№` до `Ответ исполнителя`;
- темно-синюю шапку с белым полужирным текстом;
- настроенные ширины столбцов, переносы, верхнее выравнивание и границы;
- двадцать пустых форматированных строк для заполнения.

При нехватке строк копируй формат последней пустой строки шаблона вниз и только после этого записывай значения.

## Корректировка сводной из PDF (добавлено)

Если нужно перепроверить заполнение `Предложения по отработке замечания` по всем PDF и заново пересобрать текущую сводную таблицу, используй:

`powershell -ExecutionPolicy Bypass -File $env:USERPROFILE\YandexDisk\1 Кодекс\skills\svodnaya-tablica-zamechaniy\scripts\fix_svodnaya_from_pdf.ps1 -RemarksFolder "$env:USERPROFILE\YandexDisk\1 Кодекс\Замечания\<папка_даты>" -WorkbookPath "$env:USERPROFILE\YandexDisk\1 Кодекс\Замечания\<папка_даты>\Сводная таблица замечаний ... .xlsx"`

Скрипт:

- создаёт backup исходного файла;
- пересобирает `Сводная`, `Свод по разделам` и листы разделов;
- применяет правило `ПБ -> 1 ПЗ`;
- выставляет `Не указано` для пустых текстовых полей.

## Отдельные файлы по разделам (добавлено)

Важно: если пользователь просит сделать отдельные файлы по разделам, всегда создавай файлы в формате:
`Замечания по Объекту <Название объекта> <Раздел> <YYYY-MM-DD>.xlsx`
с колонкой `коментарий проектировщика.`.

Не используй формат `remarks_<Раздел>.xlsx`, если пользователь прямо не попросил именно
«разбить крайнюю редакцию», «создать remarks-файлы» или не указал этот формат явно.

Если объект известен из контекста, используй его в имени файлов. Для БМК Панфилова:
`Замечания по Объекту БМК Панфилова <Раздел> <YYYY-MM-DD>.xlsx`.

Если нужно сделать отдельный `.xlsx` на каждый раздел с именем:
`Замечания по Объекту Кашира БМК 6.0 <Раздел> <дата>.xlsx`, используй:

`powershell -ExecutionPolicy Bypass -File $env:USERPROFILE\YandexDisk\1 Кодекс\skills\svodnaya-tablica-zamechaniy\scripts\refresh_section_files_with_style.ps1 -SourceWorkbook "$env:USERPROFILE\YandexDisk\1 Кодекс\Замечания\<папка_даты>\Сводная таблица замечаний ... .xlsx" -RemarksFolder "$env:USERPROFILE\YandexDisk\1 Кодекс\Замечания\<папка_даты>" -OutputDir "$env:USERPROFILE\YandexDisk\1 Кодекс\Замечания\<папка_даты>\sections_named_<дата>" -Prefix "Замечания по Объекту Кашира БМК 6.0" -DateStamp "<YYYY-MM-DD>" -CommentHeader "коментарий проектировщика."`

Скрипт:

- создаёт отдельные файлы по разделам;
- добавляет колонку `коментарий проектировщика.`;
- применяет стиль шапки (цветной фон, белый шрифт), границы, переносы, авто-высоты строк и целевые ширины колонок;
- повторно сверяет `Предложения по отработке замечания` по PDF и если поле действительно пустое, ставит `Не указано`.

## Разбиение крайней редакции сводной по разделам ПД (добавлено)

Если пользователь просит: «найди сводную таблицу крайней редакции и создай отдельные файлы по разделам ПД», выполняй так:

1. Найди последний файл `Сводная таблица замечаний*.xlsx` по `LastWriteTime` в `Кодекс/Замечания`.
2. Запусти разбиение через `split_svodnaya_by_section.ps1`.
3. Сохрани файлы в папку, указанную пользователем (по умолчанию — папка исходной сводной).

Команда поиска крайней редакции:

`Get-ChildItem -Path "$env:USERPROFILE\YandexDisk\1 Кодекс\Замечания" -Recurse -File -Filter "*Сводная таблица замечаний*.xlsx" | Sort-Object LastWriteTime -Descending | Select-Object -First 1 FullName,LastWriteTime`

Команда разбиения (в папку исходной сводной):

`powershell -ExecutionPolicy Bypass -File $env:USERPROFILE\YandexDisk\1 Кодекс\skills\svodnaya-tablica-zamechaniy\scripts\split_svodnaya_by_section.ps1 -SourcePath "$env:USERPROFILE\YandexDisk\1 Кодекс\Замечания\<папка_даты>\Сводная таблица замечаний ... .xlsx" -OutputDir "$env:USERPROFILE\YandexDisk\1 Кодекс\Замечания\<папка_даты>"`

Команда разбиения (в текущую рабочую папку навыка):

`powershell -ExecutionPolicy Bypass -File $env:USERPROFILE\YandexDisk\1 Кодекс\skills\svodnaya-tablica-zamechaniy\scripts\split_svodnaya_by_section.ps1 -SourcePath "$env:USERPROFILE\YandexDisk\1 Кодекс\Замечания\<папка_даты>\Сводная таблица замечаний ... .xlsx" -OutputDir "$env:USERPROFILE\YandexDisk\1 Кодекс\skills\svodnaya-tablica-zamechaniy"`

Результат:

- создаются файлы вида `remarks_<Раздел>.xlsx`;
- один файл на каждый раздел из колонки `Раздел`;
- структура и стиль сохраняются в формате, пригодном для передачи проектировщикам.

## Явный список PDF (добавлено)

Если пользователь перечислил конкретные пути PDF (Downloads или любые другие), обрабатывай именно их. Не ищи архивы в `Кодекс/Замечания`, пока пользователь сам не попросил пакет из этой папки.

Если в одном запросе смешаны несколько разделов эксперта (например УСС и СА), делай одну сводную таблицу на весь список, если пользователь не попросил отдельные файлы.

## OpenClaw и Windows (добавлено)

Для OpenClaw и Windows Companion:

- Не используй `computer` / CUA / скриншоты PDF. Это длинная задача, шлюз уходит в timeout.
- Не разбирай PDF по одному в чате. Запусти скрипт на весь список.
- `pdftotext` на Windows может отсутствовать. Рабочий путь: Python + PyMuPDF (`fitz`) для layout и `pypdf` для длинных блоков.
- Шаблон: `{baseDir}/assets/template-summary-remarks.xlsx`.
- Если Excel держит файл открытым, сохрани копию с суффиксом времени.

Команда:

```powershell
python "{baseDir}/scripts/build_from_pdf_list.py" --out "C:\путь\Сводная таблица замечаний <разделы> yyyy-MM-dd.xlsx" "C:\path\file1.pdf" "C:\path\file2.pdf"
```

Скрипт:

- извлекает layout и обычный текст;
- заполняет восемь колонок шаблона;
- поле формы `Предложения...` оставляет как в бланке (`Не указано`, если пусто);
- переписку `Обсуждение` пишет в `Ответ исполнителя`.

После сборки отрендери лист и проверь, что текст не обрезан.
