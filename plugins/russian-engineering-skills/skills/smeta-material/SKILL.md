# Смета Материал

Работать с выгрузками сметного программного комплекса **«Помощник инженера-сметчика»**. Вносить материалы из счета в отдельную копию `.sm`, одновременно создавая строки основной сметы и связанные ресурсы печатных форм.

## Порядок работы

1. Сохранить исходный `.sm` без изменений.
2. До изменения выполнить проверку сметы по [estimate-check.md](references/estimate-check.md). Обязательно:
   - определить даты сметы/договора/выполнения работ;
   - прочитать из `ParametersSm` период индексов, область, зону и метод расчета;
   - начать поиск с [belstroyka.by](https://belstroyka.by/), затем открыть указанную там первичную публикацию РНТЦ, МАиС или нормативного банка;
   - найти в интернете официально опубликованные индексы для соответствующих даты, региона и метода;
   - сопоставить примененный период и значения с официальным источником и привести ссылку;
   - не менять индексы автоматически: выявленное расхождение сначала зафиксировать и запросить решение пользователя.
3. Прочитать счет подходящим навыком:
   - XLSX/XLS/CSV — `spreadsheets`;
   - PDF — `pdf` или `read-pdf`.
4. Извлечь для каждой строки точные `name`, `unit`, `quantity`, `unit_price` и `amount`. Не переносить заголовки, итоги и пустые строки.
5. Проверить `round(quantity * unit_price, 2) = amount` по каждой строке и общий итог счета.
6. Создать временный UTF-8 JSON по схеме из [materials-json.md](references/materials-json.md).
7. Запустить [import-smeta-materials.ps1](scripts/import-smeta-materials.ps1), указав исходный `.sm`, новый выходной файл, JSON и объект.
8. Повторно прочитать готовый `.sm` и проверить:
   - число новых строк `TRascenkiFull`;
   - число связанных строк `TVibMater`;
   - связь `TVibMater.KodRascenki = TRascenkiFull.Kod`;
   - совпадение наименований, единиц, количеств, цен и сумм;
   - одинаковый итог по `Stoim91`, `FaktStoim` и исходному счету;
   - `manualcalc=True` только у добавленных ручных позиций;
   - исходный файл не изменен.
9. Передать пользователю только новую проверенную копию и краткий протокол проверки сметы: индексы, критические ошибки, существенные замечания и результат внесения материалов. Явно назвать устаревшие промежуточные версии, если они существуют.

## Запуск

```powershell
& "$env:USERPROFILE\.codex\skills\smeta-material\scripts\import-smeta-materials.ps1" `
  -SourceSm "C:\path\source.sm" `
  -OutputSm "C:\path\source_с материалами.sm" `
  -MaterialsJson "C:\path\materials.json" `
  -ObjectContains "фрагмент наименования объекта" `
  -CodePrefix "MAT-236"
```

Если известен внутренний номер сметы, использовать `-NumberSm 215`. При одновременной передаче `-NumberSm` и `-ObjectContains` скрипт проверяет их соответствие.

## Критические правила

- Не записывать материалы только в `TRascenkiFull`: они появятся в редакторе, но печатная расшифровка будет пустой.
- Не записывать материалы только в `TNewTovar`: они не появятся отдельными позициями основной сметы.
- Для каждой новой позиции создавать пару:
  - `TRascenkiFull` — строка в окне сметы;
  - `TVibMater` — строка для печатных форм.
- Ставить `manualcalc=True` («Запр. пересчет»), потому что произвольного кода нет в нормативной базе. Это сохраняет ручную цену при общем пересчете.
- Не ставить `ExcludeRasc`: это исключает позицию из расчета.
- Для счета без НДС использовать `NDS=0`; базовую и фактическую цены/стоимости заполнять одинаково, чтобы разные печатные формы показывали один итог.
- Не использовать случайные внутренние `Kod`: брать значения выше текущего максимума. Произвольным может быть только видимый код `Rascenka`, он должен быть уникальным и не длиннее 16 символов.
- Не перезаписывать существующий выходной файл. Создавать новую понятную копию.
- Проверять индексы только по официальным или первичным источникам. Не брать значения из поискового сниппета, форума или непроверенной таблицы.
- Использовать [страницу обновлений Belstroyka](https://belstroyka.by/obnow.html) для проверки версии программы, изменений нормативной базы, методик и ссылок на документы. Не считать сообщение об обновлении заменой самому нормативному документу, если на странице дана ссылка на первоисточник.
- Если дата в смете, договоре, акте и счете различается, перечислить все даты и объяснить, какая из них нормативно определяет период индексов; при неоднозначности запросить решение пользователя.

## Диагностика

Подробная схема и назначение полей приведены в [access-schema.md](references/access-schema.md). Если провайдер Microsoft ACE OLEDB отсутствует, не менять базу частично: удалить незавершенную копию и сообщить, что требуется Access Database Engine.
