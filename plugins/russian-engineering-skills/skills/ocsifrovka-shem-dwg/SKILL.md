# Оцифровка схем в DWG

Цель: нативный редактируемый чертёж, визуально совпадающий с исходной схемой.
Не трассировать растр в полилинии (`potrace` и аналоги). Не оставлять фото как IMAGE/PDF-подложку в выдаче.

Скрипты навыка запускать из `scripts/` этого каталога. Работать только с копиями в отдельной рабочей папке проекта, исходное фото не перезаписывать.

## Когда читать справочники

- Перед первой сборкой сцены — [references/scene-schema.md](references/scene-schema.md).
- При выборе типа УГО — [references/symbols.md](references/symbols.md).
- Перед SAVEAS в DWG и Core Console — [references/autocad.md](references/autocad.md).

## Рабочая папка

```text
<объект>/_ocsifrovka/<имя-схемы>/
  source.jpg          копия исходника
  work/               preprocess, calib, guide
  scene.json          модель чертежа
  scheme.dxf          всегда
  scheme.dwg          если AutoCAD SAVEAS прошёл
  preview.png         рендер DXF
  overlay.png         исходник vs рендер
  report.md           нечитаемые фрагменты и расхождения
```

Для AutoCAD и скриптов использовать ASCII-пути, например `C:\Temp\ocsifrovka_work`.

## Чеклист

Скопировать и вести:

```text
- [ ] Копия исходника, рабочая папка, ASCII-temp при работе через AutoCAD
- [ ] preprocess: work/source_work.png, work/source_guide.png, work/calib.json
- [ ] Прочитаны guide и work-изображение, блики/отражения людей игнорируются
- [ ] scene.json: формат листа, трубы, УГО, тексты, выноски, нечитаемое
- [ ] validate_scene.py без ошибок
- [ ] build_dxf.py → DXF без растровых вхождений
- [ ] render_preview.py и make_overlay.py
- [ ] Итерации scene.json по overlay до совпадения состава, связей и надписей
- [ ] convert_to_dwg.ps1 при доступном AutoCAD LT
- [ ] Выдача: DWG/DXF, список нечитаемых мест, без подложки
```

## Шаг 1. Подготовка растра

```powershell
python scripts/preprocess_image.py "<source>" --out-dir "<work>" --paper A3 --orientation landscape
```

Если кадр уже ровный скан — добавить `--no-warp`. Формат листа не угадывать по плотности схемы: по умолчанию A3 landscape, иначе брать явное указание пользователя или штамп.

Координаты CAD: миллиметры, начало в левом нижнем углу листа. Формула и CLI:

```powershell
python scripts/map_coords.py "<work>\calib.json" 1234,567 2000,800
```

## Шаг 2. Восстановить модель, не картинку

Смотреть `source_guide.png` (сетка в мм) и `source_work.png`. Собрать `scene.json`.

Обязательные инварианты:

- Трубы — `LINE`/`LWPOLYLINE` по узлам. Ортогональны, если так на исходнике; 45° сохранять, если так на исходнике.
- Изометрию не зеркалить. Диагональ `/` (снизу-слева вверх-направо, Δx и Δy одного знака) и диагональ `\` — разные рисунки. Брать ту, что на фото, а не «удобную» для компановки.
- **Никаких упрощений.** Не схлопывать лист в одну линию с одним изломом. Повторять полную топологию исходника: отдельные коллекторы, вертикали, байпасы, изометрический узел на своём месте, все читаемые аппараты и надписи, плотность как на картинке.
- Арматура и КИП — блоки из каталога `type`, а не набор случайных отрезков.
- Надписи — `MTEXT`/`TEXT`, кириллица точно как на схеме, включая `Ду`, `кгс/см²`, марки.
- Нечитаемый из-за блика текст не выдумывать: объект в `unreadable`, на чертеже плейсхолдер или пропуск.
- Блок «Утверждаю» и печать не рисовать, пока пользователь прямо не попросит. Рамку листа не рисовать (`meta.draw_frame`). Рукописную подпись не подделывать.
- Временная подложка для сверки допустима только в рабочей копии и должна быть удалена до выдачи.

## Шаг 3. Сборка и сверка

```powershell
python scripts/validate_scene.py "<scene.json>"
python scripts/build_dxf.py "<scene.json>" "<scheme.dxf>"
python scripts/render_preview.py "<scheme.dxf>" "<preview.png>" --calib "<work>\calib.json"
python scripts/make_overlay.py "<work>\source_work.png" "<preview.png>" "<overlay.png>"
```

Смотреть overlay. Красный — только исходник, голубой — только DXF, тёмное — совпадение. Править `scene.json` и пересобирать. Не править DXF вручную в обход сцены, пока идёт подгонка.

Считать лист готовым, когда:

- есть все читаемые аппараты, трубы, стрелки, свечи, байпасы и подписи;
- топология совпадает (что с чем связано);
- подписи стоят у тех же элементов;
- нет растра в DXF/DWG;
- нечитаемые места перечислены в `report.md`.

## Шаг 4. DWG

```powershell
powershell -NoProfile -File scripts/convert_to_dwg.ps1 -Dxf "<scheme.dxf>" -OutDwg "<scheme.dwg>"
```

Если Core Console недоступен или SAVEAS не прошёл — выдать DXF как основной CAD-файл и явно сказать, что DWG получится через «Сохранить как» в AutoCAD LT. Не называть DXF с подложкой готовым чертежом.

## Запрещено

- Выдавать трассированный растр, PDF-подложку или кашу из коротких полилиний.
- Упрощать компоновку, пропускать читаемые узлы, спрямлять изометрию, переносить аппараты «чтобы влезло».
- Додумывать марки регуляторов, Ду, давления и текст, которого не видно.
- Менять технологию схемы «для красоты».
- Править исходный DWG проекта автоматизации этим навыком.
